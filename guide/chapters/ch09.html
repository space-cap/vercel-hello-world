Day 5: 토스페이먼츠 결제 연동 —
첫 100원의 쾌감과 보안 2대 함정

⏱ 약 5분·PART 3 · 실행

첫 결제가 실제로 터지는 순간은 창업가 인생에서 잊지 못할 경험입니다. "코드만 있는 화면"이 "고객이 돈을 지불하는 진짜 비즈니스"로 승격되는 날이기 때문입니다.

토스페이먼츠 연동 3단계

01
토스페이먼츠 개발자센터 가입 및 API Key 발급

developers.tosspayments.com 에서 회원가입 후 [내 개발 정보]에서 "테스트 클라이언트 키"와 "테스트 시크릿 키"를 발급받아 프로젝트의 .env.local 에 저장합니다.

02
결제창 SDK 호출 (프론트엔드 UI)

Cursor에게 아래 PROMPT #7을 주면 결제 위젯/결제창 호출 컴포넌트를 즉시 생성해 줍니다. 사용자가 [결제하기]를 누르면 토스 간편결제 창이 뜹니다.

03
결제 승인 웹훅 (서버 사이드 API Route)

고객이 결제를 마쳤다고 바로 끝이 아닙니다. 우리 백엔드 서버가 토스 승인 API를 호출하여 "진짜 결제가 맞는지" 최종 확인하고 Supabase 데이터베이스에 구매 기록을 기록해야 합니다.

📋 PROMPT #7 — 토스페이먼츠 결제창 v2 및 승인 API 완성본 
Next.js 15 App Router와 토스페이먼츠 결제창 SDK를 연동해 주세요.

결제 흐름:
1. 사용자가 상품 결제 버튼 클릭 (/pricing 또는 /checkout)
2. 토스페이먼츠 결제창 오픈 (금액: [금액]원, 주문명: [주문명])
3. 성공 시 /payment/success 로 리다이렉트 (orderId, paymentKey, amount 파라미터 전달)
4. /payment/success 페이지에서 백엔드 승인 API(/api/payment/confirm) 호출
5. 승인 완료 시 Supabase orders 테이블에 status='PAID' 저장 및 유저 크레딧 충전

필수 보안 조건:
- TOSS_SECRET_KEY는 오직 백엔드 API route(서버 사이드)에서만 사용해야 하며, 클라이언트에 절대 노출되지 않도록 할 것.
- 결제 요청 금액과 실제 승인 금액이 일치하는지 서버에서 교차 검증할 것.

작성할 파일 목록:
- components/PaymentCheckout.tsx
- app/payment/success/page.tsx
- app/api/payment/confirm/route.ts

⚠️ 비개발자가 결제 연동 시 저지르는 2대 치명적 실수

🚨
실수 1: 시크릿 키(Secret Key) 클라이언트 노출
NEXT_PUBLIC_ 접두사를 시크릿 키 앞에 붙이면 웹 브라우저의 [개발자 도구]에서 누구나 대표님의 결제 비밀키를 볼 수 있게 됩니다. 결제 취소나 무단 승인 등 금전적 사고로 이어지므로, 시크릿 키는 반드시 접두사 없는 순수 환경변수로 백엔드에서만 불러와야 합니다.

실수 2: 클라이언트 금액 변조(F12 조작) 공격 방어 누락
악의적인 사용자가 개발자 도구에서 10,000원짜리 결제 금액을 100원으로 변조해 결제할 수 있습니다. 반드시 백엔드 승인 API에서 "원래 DB에 저장된 주문 금액과 토스가 승인한 금액이 정확히 일치하는지" 대조해야 합니다.

VibeCraft 솔루션:
결제는 대표님의 매출과 직결되는 가장 민감한 영역입니다. 토스페이먼츠 사업자 심사, 계약, 그리고 위변조 방지 완벽 웹훅 세팅까지 VibeCraft 납품 패키지에는 이 모든 보안 장치가 100% 턴키로 탑재되어 첫날부터 안심하고 카드 결제를 받을 수 있습니다.
