APPENDIX D
초보자가 반드시 겪는 Next.js & Supabase 멘붕 에러 Top 8 탈출기
흰 화면과 터미널 빨간 줄을 1분 만에 해결하는 응급 처방전

바이브 코딩으로 개발하다 보면 갑자기 빌드가 멈추거나, 화면에 무서운 빨간 글씨가 뜨며 멘붕에 빠지는 순간이 옵니다. 하지만 이 에러들의 95%는 모든 1인 개발자가 똑같이 겪는 패턴화된 이슈입니다. 가장 자주 터지는 8가지 에러의 원인과 1분 해결 코드를 한곳에 모았습니다.

🚨 Error 1. Text content does not match server-rendered HTML (Hydration Failed)

증상: 로컬에서는 잘 되다가 새로고침하면 콘솔에 Hydration failed because the initial UI does not match... 경고가 뜨며 화면이 깜빡입니다.

원인: 서버에서 렌더링할 때의 값(예: new Date(), Math.random(), localStorage)과 브라우저에서 렌더링할 때의 값이 일치하지 않기 때문입니다.

💡 해결책: useEffect 지연 마운트 패턴 적용
'use client'; import { useState, useEffect } from 'react'; export default function MyComponent() { const [mounted, setMounted] = useState(false); useEffect(() => { setMounted(true); // 브라우저에 마운트된 후에만 클라이언트 전용 로직 실행 }, []); if (!mounted) return null; // 또는 스켈레톤 로딩 UI return <div>현재 시간: {new Date().toLocaleTimeString()}</div>; }

🚨 Error 2. Dynamic server usage: Page couldn't be rendered statically

증상: Vercel 배포 빌드 시 Error: Dynamic server usage: Route /dashboard couldn't be rendered statically because it used cookies or searchParams 에러로 배포 실패.

원인: Next.js는 기본적으로 정적 HTML 빌드를 시도하는데, 페이지 내부에서 유저 로그인 세션 쿠키나 URL 쿼리 파라미터를 읽으려 했기 때문입니다.

💡 해결책: 해당 페이지 상단에 dynamic 강제 지정
// app/dashboard/page.tsx 맨 위에 1줄 추가 export const dynamic = 'force-dynamic'; export default async function DashboardPage() { // 쿠키 및 Supabase auth 세션 안전하게 조회 가능! ... }

🚨 Error 3. Supabase 쿼리는 성공인데 데이터가 무조건 빈 배열 ([])로 옴

증상: Supabase 대시보드 테이블엔 데이터가 분명히 있는데, 코드로 supabase.from('posts').select('*')를 실행하면 에러 없이 data: []만 옵니다.

원인: Supabase의 철통 보안인 **Row Level Security (RLS)**가 켜져 있는데, 읽기 허용 정책(Policy)을 만들어주지 않았기 때문입니다.

💡 해결책: Supabase SQL Editor에서 읽기 정책 추가
-- 누구나 읽을 수 있는 공개 테이블인 경우: CREATE POLICY "Public Read Access" ON public.posts FOR SELECT USING (true); -- 본인 데이터만 읽을 수 있는 비공개 테이블인 경우: CREATE POLICY "User Own Data Access" ON public.posts FOR SELECT USING (auth.uid() = user_id);

🚨 Error 4. Vercel 배포 후 API 키 / 환경변수가 undefined로 뜸

증상: 내 컴퓨터(`.env.local`)에서는 완벽하게 로그인되는데, Vercel 사이트에 들어가면 "Supabase URL is required" 에러가 발생합니다.

원인: 보안상 `.env.local` 파일은 깃허브에 올라가지 않기 때문에, Vercel 클라우드 대시보드에 환경변수를 별도로 등록해주어야 합니다.

💡 해결 순서

1. Vercel 대시보드 ➔ 프로젝트 선택 ➔ Settings ➔ Environment Variables 이동.
2. NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY 등을 등록.
3. 상단 Deployments 메뉴에서 최신 배포 우측의 ... 클릭 ➔ Redeploy 실행!

🚨 Error 5. 토스페이먼츠 결제창은 뜨는데 최종 승인 시 401 Unauthorized

증상: 결제창에서 카드 정보 입력 후 리다이렉트되었는데, https://api.tosspayments.com/v1/payments/confirm 호출에서 INVALID_SECRET_KEY 에러 발생.

원인: 토스페이먼츠 인증 헤더는 시크릿 키 뒤에 콜론(:)을 붙인 뒤 Base64 인코딩을 거쳐야 합니다.

💡 해결책: Base64 인코딩 올바른 헤더 코드
const secretKey = process.env.TOSS_PAYMENTS_SECRET_KEY; // 주의: secretKey 뒤에 콜론(:) 필수! const basicToken = Buffer.from(`${secretKey}:`).toString('base64'); const response = await fetch('https://api.tosspayments.com/v1/payments/confirm', { method: 'POST', headers: { 'Authorization': `Basic ${basicToken}`, 'Content-Type': 'application/json' }, body: JSON.stringify({ paymentKey, orderId, amount }) });

🚨 Error 6. CORS policy: No 'Access-Control-Allow-Origin' header

증상: 클라이언트 컴포넌트에서 외부 API를 직접 호출할 때 브라우저 보안 정책으로 통신 차단.

원인: 브라우저는 다른 도메인으로의 무단 AJAX 요청을 차단합니다.

💡 해결책: 브라우저에서 직접 외부 API를 호출하지 말고, Next.js 내부의 Route Handler(/app/api/.../route.ts)를 거치는 프록시 패턴을 사용하세요. 서버 간 통신은 CORS 제약을 전혀 받지 않습니다.

🚨 Error 7. Tailwind CSS 클래스를 추가했는데 스타일이 전혀 안 먹힐 때

증상: className="bg-emerald-500 rounded-2xl"을 넣었는데 스타일이 전혀 적용되지 않고 기본 글자만 나옵니다.

원인: tailwind.config.js의 content 경로에 새로 만든 폴더 경로가 누락되었거나, 동적 클래스명(예: bg-${color}-500)을 문자열 합성으로 작성했기 때문입니다. (Tailwind 빌더는 동적 문자열을 감지하지 못합니다.)

🚨 Error 8. 실수로 .env.local 비밀 키 파일을 GitHub에 커밋했을 때

증상: Supabase 서비스 롤 키나 토스 비밀 키가 깃허브 공개 레포지토리에 푸시되어 알림 메일이 빗발칠 때.

💡 해결책: Git 캐시 즉시 제거 및 키 재발급 3단계
# 1. 로컬 파일은 보존하면서 Git 추적에서만 제거 git rm --cached .env.local # 2. .gitignore 파일 맨 밑에 .env.local 추가 확인 후 커밋 & 푸시 git commit -m "fix: remove sensitive env file from git tracking" git push origin main # 3. 중요: 이미 노출된 키는 Supabase/토스 대시보드에서 반드시 [Roll Key / 재발급] 버튼을 눌러 교체하세요!
