킬러 기능 추출 프롬프트:
군더더기를 걷어내는 AI 파트너십

⏱ 약 4분·PART 2 · 기획

기획의 핵심은 추가가 아닌 제거입니다. "이것도 넣어줘"가 아니라 "이것을 빼도 첫 결제는 가능한가?"를 질문하는 창업가가 7일 안에 런칭합니다.

📖
기능이 늘어날수록 매몰 비용 함정에 빠집니다
인천의 이OO 씨는 헬스장 회원 관리 SaaS를 만들기로 했습니다. 초안에는 23개 기능이 있었습니다. PT 수업 예약, 운동 기록 트래커, 식단 일지, 회원 메시지 발송, 강사별 통계... 6개월이 지나도 개발이 끝나지 않았고, 그 사이 경쟁사 2곳이 먼저 시장에 나왔습니다.

"회원이 월 회비를 자동 결제하는 기능 하나만"으로 시작했다면, 3일 만에 만들 수 있었습니다.

Before / After: 기능 다이어트 실전 비교

❌ 흔한 기획 (12개 기능, 개발 기간 3개월+)
  • 회원가입 / 소셜 로그인 5종
  • 카드뉴스 생성 (AI)
  • AI 카피라이팅 보조
  • 템플릿 마켓플레이스
  • 팀 협업 / 권한 관리
  • 폴더 & 프로젝트 관리
  • 브랜드 키트 (색상/폰트 저장)
  • SNS 스케줄 예약 발행
  • 통계 대시보드 & 리포트
  • 유료 구독 + 1회 결제 옵션
  • 이메일 자동 발송
  • 관리자 페이지
✅ MVP 기획 (3개 기능, 개발 기간 4일)
  • 이메일 회원가입 (소셜 로그인 없음)
  • 키워드 입력 → AI 카드뉴스 5장 즉시 생성
  • 완성된 이미지 다운로드 + 토스 1회 결제
런칭 후 첫 주 유료 결제: 37건 (185,000원)

기능을 제거하는 판단 기준 — "MUST / SHOULD / CUT" 프레임

MUST
"이 기능이 없으면 고객이 결제를 완료할 수 없다"

회원가입, 핵심 기능 1개, 결제 버튼 — 이것이 전부입니다. Week 1에 이것만 만듭니다.

SHOULD
"있으면 더 편리하지만, 없어도 결제는 가능하다"

마이페이지, 이력 조회, 프로필 수정 — Week 2~3에 추가합니다. 실제 고객이 요청할 때 만드세요.

CUT
"내가 만들고 싶어서 넣는 기능"

관리자 통계, 팀 협업, 브랜드 키트 — 초기 버전에서 완전히 삭제하세요. 고객이 없는데 관리자가 필요 없습니다.

📋 PROMPT #2 — MUST/SHOULD/CUT 기능 분류 프롬프트 
아래는 내가 계획 중인 서비스의 기능 목록입니다:
[기능 목록을 줄바꿈으로 나열하세요]

다음 기준으로 각 기능을 분류해 주세요:
- MUST (없으면 첫 결제가 불가능): 반드시 Day 7 이전에 개발
- SHOULD (있으면 좋지만 없어도 결제 가능): Week 2 이후 추가
- NICE (있으면 좋은 꾸미기 기능): Month 2 이후 추가
- CUT (절대 초기 버전에 넣지 말 것): 영구 삭제 또는 Pivot 시 재검토

분류 후, MUST 항목만으로 구성된 "7일 MVP 기능 목록"과
"런칭 후 2주 내 추가할 SHOULD 기능 목록"을 분리해서 정리해 주세요.
