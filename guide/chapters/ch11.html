.cursorrules 전략:
당신의 제품을 AI가 영구적으로 이해하게 만드는 법

⏱ 약 5분·PART 4 · 외주 졸업

.cursorrules는 Cursor AI에게 "이 프로젝트는 이런 아키텍처이고, 어떤 파일도 함부로 지우지 말라"는 영구 기억을 심어주는 파일입니다. 이것이 바로 비개발자가 외주사에 평생 종속되지 않고 스스로 서비스를 운영할 수 있는 '외주 졸업 키트'의 핵심 비결입니다.

3가지 비즈니스 유형별 .cursorrules 실전 템플릿

📋 Type A — B2C SaaS / 월 구독형 서비스용 .cursorrules 
# Project Type: B2C SaaS with Subscription
# Stack: Next.js 15, Supabase, Toss Payments / Stripe, TypeScript, Tailwind CSS
# Role: Senior Fullstack Architect for a non-technical solo founder

## Core Architecture Rules
1. Always preserve the subscription status check logic in middleware.ts. Non-paying users must never access /dashboard.
2. Never expose secret keys; all payment operations and Supabase service-role calls must happen strictly in /app/api/*.
3. Use Row Level Security (RLS) in Supabase — every table must have user-scoped policies (auth.uid() = user_id).
4. Write idempotent webhook handlers — duplicate payment events with the same orderId must be safely ignored.
5. All user-facing UI text must be in polished Korean; code identifiers in clean English.

## Safe Modification Rules
- When the user asks for a UI change, only modify the specific component. Never rewrite the entire parent layout.
- Always provide the complete file without truncation or ellipses (...).
📋 Type B — 디지털 콘텐츠 / 단건 결제 마켓플레이스용 .cursorrules 
# Project Type: Digital Asset Marketplace with One-time Payment
# Stack: Next.js 15, Supabase Storage, Toss Payments, TypeScript, Tailwind

## Core Architecture Rules
1. Payment confirmation must strictly occur server-side — never trust client-side parameters.
2. Digital download links must be generated as temporary signed URLs (15-minute expiration).
3. The Supabase Storage bucket for paid files must be PRIVATE — never public.
4. Every valid purchase must insert a verified row in the 'orders' table before granting asset access.
5. Prevent duplicate downloads by checking order verification token in the API handler.
📋 Type C — 커뮤니티 & 유료 멤버십 플랫폼용 .cursorrules 
# Project Type: Community & Membership Platform
# Stack: Next.js 15 App Router, Supabase Auth & DB, Toss Recurring, Tailwind

## Core Architecture Rules
1. Gate premium content by inspecting user's active membership tier (FREE | PRO | VIP) server-side.
2. Never send blurred premium content HTML to non-paying users — fetch from DB only if authorized.
3. Optimize page load speeds using Next.js ISR (Incremental Static Regeneration) where possible.
4. Provide immediate visual feedback (loading spinners, optimistic updates) for all user actions.
💡
왜 기존 외주사는 .cursorrules를 주지 않을까요?
외주사의 핵심 수익원은 초기 개발비가 아니라 "런칭 후 매달 청구하는 유지보수 계약금과 사소한 수정 비용"입니다. 고객이 스스로 AI와 대화하며 버튼을 바꾸고 새 페이지를 추가할 수 있게 되면, 외주사의 밥줄이 끊기기 때문입니다.

VibeCraft는 정반대의 길을 갑니다:
우리는 대표님이 외주사 없이 100% 자립하는 것을 목표로 합니다. 7일 만에 완성된 제품을 넘겨드릴 때, 해당 프로젝트의 파일 트리와 데이터베이스 구조를 100% 학습시킨 [맞춤형 .cursorrules]를 함께 납품합니다. 대표님은 이것 하나만 Cursor 폴더에 넣어두면 평생 유지보수 비용 0원으로 서비스를 마음껏 진화시킬 수 있습니다.
