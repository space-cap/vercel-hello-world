## 0. 이 전자책이 탄생하는 이유 (Why)

전 세계 1인 창업 시장에서 "AI로 코딩한다"는 말은 이제 흔합니다.  
하지만 **실제로 돈을 받는 제품을 7일 안에 완성해 런칭까지 한 사람**은 극히 드뭅니다.

이 책은 그 간극을 메웁니다.  
단순한 기술 튜토리얼이 아닌, **비즈니스 검증 → 제품 완성 → 첫 결제 수취 → 외주 종속 탈출**까지의 완전한 여정을 담은 **실전 전략서**입니다.

## 3. 챕터별 상세 콘텐츠 설계

### PART 1 — 마인드셋

#### Chapter 01 | 외주 개발의 불편한 진실
- **핵심 메시지**: 외주 개발사의 비즈니스 모델은 '빠른 납품'이 아닌 '느린 납품'에서 더 많은 돈을 번다.
- **주요 내용**:
  - 외주 계약서의 모호한 범위(Scope)가 어떻게 추가 비용으로 돌변하는가
  - 소스코드 소유권 조항을 반드시 확인해야 하는 이유
  - 실제 사례: 5,000만 원 외주 → 런칭 실패 케이스 분석
- **독자 실습**: 외주 견적서 리뷰 체크리스트 (15개 항목)

#### Chapter 02 | "기능이 많을수록 성공한다"는 착각
- **핵심 메시지**: Facebook도 처음에는 사진 공유 없이 '대학 친구 찾기' 단 하나였다.
- **주요 내용**:
  - Feature Creep(기능 비대증)의 심리적 원인
  - 성공한 스타트업의 초기 MVP 기능 수 분석 (평균 1.8개)
  - "이 기능 없으면 고객이 돈을 안 낼까?" 테스트 기법
- **독자 실습**: 아이디어 기능 목록에서 킬러 기능 1개를 선발하는 워크시트

#### Chapter 03 | 7일 스프린트 철학
- **핵심 메시지**: 7일 안에 배포 못 하면 3개월이 지나도 배포 못 한다.
- **주요 내용**:
  - 소프트웨어 프로젝트 지연의 파킨슨 법칙
  - 린 스타트업(Lean Startup)과 바이브코딩의 교차점
  - 7일 스프린트 데일리 타임박스 설계 방법

## 4. 디자인 & 레이아웃 방향

- **테마**: "프리미엄 테크 크래프트 — 해커의 실용성 + 디자이너의 미학"

## 5. 기술 구현 계획

### 5.1 파일 구조

```
guide/
├── index.html           ← 메인 웹북 (단일 페이지)
├── style.css            ← 웹 리딩 스타일 + @media print PDF 최적화
├── script.js            ← 인터랙션 전체
└── assets/
    └── images/          ← 챕터 일러스트, DB 다이어그램 이미지
```

### 5.2 HTML 웹북 핵심 기능 목록

| 기능 | 구현 방법 | 우선순위 |
|------|-----------|----------|
| 스크롤 기반 읽기 진행률 바 | JavaScript scroll event | P0 |
| 챕터별 프롬프트 원클릭 복사 | navigator.clipboard.writeText | P0 |
| PDF 출력 (@media print) | window.print() + 전용 CSS | P0 |
| 사이드바 목차 스크롤 하이라이트 | IntersectionObserver | P1 |
| 다크/라이트 모드 토글 | CSS Variables + localStorage | P1 |
| 현재 챕터 읽기 예상 시간 표시 | 글자 수 기반 계산 (분당 500자) | P2 |
| 마지막 읽은 위치 자동 기억 | sessionStorage | P2 |

### 5.3 PDF 최적화 (@media print 세부 스펙)
- **용지 크기**: A4 세로 (210mm × 297mm)
- **여백**: 상하 2cm / 좌우 2.5cm
- **챕터 구분**: `page-break-before: always`
- **숨길 요소**: 헤더 바, 복사 버튼, 진행률 바, 모든 인터랙티브 UI
- **컬러 치환**: 배경 #ffffff / 본문 #111111 / 코드블록 #f5f5f5

## 6. 콘텐츠 품질 기준 (Editorial Standards)

### 6.1 문장 원칙
1. **1문장 = 1개 메시지**: 2가지 이상의 내용을 한 문장에 넣지 않는다.
2. **능동태 우선**: "~할 수 있습니다" → "~하세요"
3. **구체적 숫자 사용**: "많은 외주사" → "국내 외주사 83%"
4. **독자 호칭**: "창업가", "대표님" (중립적, 상향 존중)

### 6.2 필수 삽입 요소 (챕터당 최소 1개)
- 📋 **프롬프트 박스**: 실제로 복사해서 쓸 수 있는 완성형 프롬프트
- ✅ **실습 워크시트**: 독자가 직접 채워넣는 빈칸/체크박스
- 💡 **실전 팁 콜아웃**: 경험자만 아는 뉘앙스 정보
- 📖 **케이스 스터디**: 실제 제품명 / 기능 수 / 완성 기간 데이터
